## 2. 背景与目标

用户希望把准备发布的图片、视频或正文直接交给 Codex，由 Codex 完成内容整理、标题与话题建议、登录检查和发布页填充。用户不需要手工拼接命令，但必须在看到最终预览并明确授权后，Skill 才能真正点击小红书发布按钮。

本产品的核心目标是：

1. 降低小红书图文和视频发布的操作成本。
2. 根据用户提供的图片或正文，生成相关且可编辑的话题建议。
3. 把“准备内容”和“真正发布”严格分开，杜绝未经确认的发布。
4. 在登录失效、素材异常或页面改版时安全停止，并给出可执行的处理建议。

## 3. 产品原则

- **预览优先**：默认行为只能填写发布页并生成预览，不得点击发布。
- **明确授权**：只有用户针对当前版本的标题、正文、话题和媒体明确表示“发布”“确认发布”等同义指令后，才允许执行真正发布。
- **最小代办**：用户只需提供原始素材和表达意图；其余格式整理、话题建议和命令编排由 Codex 完成。
- **内容可控**：Codex 的标题、正文或话题建议均需展示给用户，用户可以修改、删除或全部拒绝。
- **失败安全**：任何关键步骤状态不明确时，默认视为未发布；不得盲目重试发布按钮。
- **本地优先**：登录资料、草稿、媒体和临时文件默认只保存在本地，不进入仓库。

## 4. 目标用户与典型场景

### 4.1 目标用户

- 希望减少重复操作的个人小红书创作者。
- 已准备图片、视频或正文，但不想手工填写创作者中心发布页的用户。
- 希望由 Codex 帮助补充标题或话题，但保留最终决定权的用户。

### 4.2 典型用户故事

1. 作为用户，我把图片和正文交给 Codex，希望它整理出可发布草稿，并在我确认后代为发布。
2. 作为用户，我只提供图片和大致意图，希望 Codex 识别图片主题，补充标题、正文草稿和相关话题供我选择。
3. 作为用户，我提供正文，希望 Codex 根据文本主题自动推荐话题，并让我在发布前修改。
4. 作为用户，我提供视频、标题和正文，希望 Codex 先填充视频发布页，等视频处理完成并让我确认后再发布。
5. 作为用户，我尚未登录，希望 Skill 打开有窗口的专用 Chrome 供我扫码，而不是继续尝试发布。

## 5. 范围与优先级

### 5.1 P0：必须具备

- 接收本地图片、图片 URL、本地视频或视频 URL，以及标题、正文和用户补充要求。
- 用户未提供标题时，可根据正文或媒体内容生成标题候选，但不得把候选当作用户已确认内容。
- 根据图片内容、正文主题或两者结合生成话题候选。
- 展示发布前预览，至少包含账号标识、发布类型、标题、正文、话题、媒体清单和是否定时发布。
- 默认不发布；真正发布必须依赖当前轮次的明确授权。
- 发布前检查登录状态、素材可用性、标题长度、正文非空和媒体类型。
- 返回清晰的预览、成功、失败或状态不确定结果。

### 5.2 P1：建议增强

- 提供多个标题或话题方案，并说明各自侧重点。
- 根据用户指定的受众、语气、账号定位或活动目标调整话题。
- 支持多账号选择，并在预览中明确当前目标账号。
- 支持定时发布，并在预览中展示具体时间和时区。

## 6. 核心流程

### 6.1 内容准备

1. 接收用户提供的正文、图片、视频、链接或本地绝对路径。
2. 判断发布类型：图文或视频；两者不能混用。
3. 检查必要信息。信息不足时，只补问会实质影响发布结果的内容；可合理生成的标题和话题先生成候选。
4. 对标题进行加权长度校验：中文及中文标点按 2 计，英文和数字按 1 计，总长度不得超过 38。
5. 生成最终草稿并进入预览流程。

### 6.2 话题自动选择

1. 有正文时，以正文主题、核心对象和目标受众为主要依据。
2. 有图片时，识别图片中的主体、场景和可见文字，用于补充或校正正文判断。
3. 图片与正文同时存在时，以用户明确表达的正文意图为主，图片信息为辅；出现冲突时向用户说明，不擅自选择误导性话题。
4. 默认建议 3 至 8 个话题，最多不超过平台允许的 10 个；优先选择准确、具体、与内容直接相关的话题。
5. 避免仅为流量添加无关热点、可能误导的身份标签或明显敏感、违规话题。
6. 在预览中单独列出话题候选，允许用户增删或替换。
7. 执行层把已确认话题放在正文最后一个非空行，格式为 `#话题1 #话题2`；脚本负责提取并在发布页逐个选择。
8. 若预期话题未能全部选中，停止自动发布或退回预览，并明确列出失败话题，等待用户决定是否继续。

### 6.3 发布前预览与授权

预览必须展示：

- 目标账号或“默认账号”。
- 图文或视频发布类型。
- 最终标题和加权长度。
- 最终正文。
- 最终话题列表。
- 图片数量及文件名/来源，或视频文件名/来源。
- 定时发布时间；未设置时显示“立即发布”。
- 当前动作说明：“仅预览，不会发布”。

授权规则：

- “看看效果”“先填一下”“测试”“预览”等指令不构成发布授权。
- 用户对旧版草稿的确认，在标题、正文、话题、媒体、账号或发布时间发生变化后失效，必须重新确认。
- 只有针对当前预览的明确发布指令，才允许调用带 `--auto-publish` 的命令。
- `--preview` 与 `--auto-publish` 不得同时使用；防御性逻辑应始终让预览优先。

### 6.4 登录检查

1. 发布或预览填充前检查创作者中心登录状态。
2. 已登录时继续；本地登录缓存只能减少重复检查，不得作为永久有效凭据。
3. 未登录时停止发布链路，并打开有窗口的专用 Chrome 登录页供用户扫码。
4. 无头模式发现未登录时，本地环境可切换为有窗口模式；远程 CDP 环境只能尝试打开远程登录页并提示用户处理。
5. 不要求用户发送密码、Cookie、二维码扫码结果或浏览器 Profile。
6. 登录完成后重新执行登录检查，再重新进入预览；不得因为登录恢复而自动发布。

### 6.5 真正发布与结果回传

1. 收到当前预览的明确授权后，显式启用 `--auto-publish`。
2. 在点击发布前再次确认浏览器连接、页面状态和表单关键字段已填充。
3. 发布成功时返回明确的成功状态和可获得的笔记链接。
4. 发布失败时返回失败阶段、可读原因和建议动作。
5. 无法确认按钮点击结果时，返回“状态不确定”，提示用户先在创作者中心核对；不得自动重复点击，以免重复发帖。

## 7. 媒体与内容边界

### 7.1 图文笔记

- 至少需要 1 张图片；无图片时不得执行图文发布。
- 支持本地绝对路径和可访问的图片 URL。
- 多张图片应保持用户给定顺序。
- URL 下载全部失败时停止；部分失败时列出失败项并回到预览，不能静默少图发布。

### 7.2 视频笔记

- 每次仅接受 1 个本地视频或 1 个视频 URL。
- 必须等待视频上传及平台处理达到可发布状态。
- 下载或处理失败时不得点击发布。

### 7.3 互斥与路径

- 图片与视频必须二选一，不能在同一笔记中混合传入。
- 本地素材优先使用绝对路径，并在执行前校验存在性。
- WSL、远程 CDP 或 UNC 路径仅在调用方明确知道远端可访问时，才允许跳过本地文件检查。

## 8. 异常与恢复策略

| 异常 | 产品行为 |
| --- | --- |
| 标题或正文为空 | 停止并请用户补充，或生成候选后重新预览 |
| 标题超长 | 给出长度与限制，生成精简候选，不自动截断后发布 |
| 本地素材不存在 | 列出无效路径并停止 |
| 媒体 URL 下载失败 | 提示更换 URL 或改用本地文件；清理已产生的临时文件 |
| Chrome 启动或 CDP 连接失败 | 停止并给出端口、进程或重启建议 |
| 未登录或登录过期 | 打开登录页，等待用户扫码后重新检查 |
| 页面选择器失效 | 停止发布并指出可能是创作者中心改版，不反复点击页面 |
| 表单填充不完整 | 保留页面供人工核对，返回失败字段，不进入自动发布 |
| 话题选择部分失败 | 列出失败话题，退回预览并等待决定 |
| 发布结果不明确 | 标记为“状态不确定”，要求先人工核对，禁止自动重试 |

## 9. 隐私、安全与合规

- Cookie 和登录态只保存在本地专用 Chrome Profile；不得写入源码、PR、日志样例或公开仓库。
- 真实账号名、笔记标题、正文、图片、视频、统计缓存和发布历史不得作为测试夹具提交。
- 临时下载的媒体和临时标题/正文文件应在任务完成或失败后按需清理；不得长期无提示保留。
- 日志不得输出 Cookie、令牌、完整二维码数据或包含敏感签名参数的媒体 URL。
- 不提供绕过验证码、风控、限流或平台安全机制的能力。
- 提醒用户遵守小红书平台规则、版权与广告合规要求；自动化可能带来限流、封禁等账号风险。
- 不默认收集遥测数据，不向第三方上传用户草稿或登录资料。

## 10. 验收标准

### 10.1 内容准备与话题

- 给定一组本地图片和正文，Codex 能输出包含标题、正文、3 至 8 个相关话题和媒体清单的预览。
- 仅给定正文时，Codex 能基于正文生成相关话题；仅给定图片和创作意图时，Codex 能基于可见内容生成话题候选。
- 用户删除或修改话题后，最终发布使用修改后的列表，不恢复已删除话题。
- 正文最后一行是纯 `#话题` 列表时，执行脚本能正确提取正文与话题；混合普通文本的行不得被误判。

### 10.2 发布安全

- 不传发布模式参数时，只填充预览，发布按钮点击次数为 0。
- 使用 `--preview` 时，即使发生错误组合，也不得点击发布。
- 只有用户明确确认当前预览后，Codex 才能构造带 `--auto-publish` 的调用。
- 任一关键字段在确认后发生变化，系统必须重新展示预览并获取新授权。
- 自动化测试不得启动 Chrome、连接小红书或执行真实发布。

### 10.3 登录与媒体

- 未登录时返回明确状态并打开可扫码的有窗口登录页，不执行发布。
- 图文缺少图片、视频缺少视频或图片与视频混用时，均在填写发布页前失败。
- 本地素材不存在或 URL 下载全部失败时，不进入发布步骤。
- 页面或发布结果状态不明确时，不自动重试发布按钮。

### 10.4 隐私检查

- 公开仓库扫描不包含 Cookie、Token、Chrome Profile、真实草稿、真实媒体和本地缓存。
- 示例和离线测试只使用虚构文本、占位链接和合成数据。

## 11. 非目标

- 不做无人值守、无需确认的批量发帖或矩阵账号群发。
- 不绕过验证码、风控、频率限制或其他平台安全机制。
- 不保证笔记流量、点赞、收藏、排名或商业转化。
- 不替用户保证内容真实性、版权归属、广告合规或平台审核结果。
- 不在本 PRD 内定义评论、回复、点赞、收藏等互动自动化能力。
- 不在本 PRD 内定义创作数据统计看板；该能力由独立的统计 Skill 负责。
- 不扩展到抖音、快手、微信公众号等其他发布平台。

## 12. 当前实现基线与待完善项

当前仓库已经具备图文/视频发布、登录检查、本地或 URL 媒体输入、标题长度检查、正文末行话题提取、发布页话题选择、预览默认值和显式 `--auto-publish` 开关。

仍需持续按本 PRD 验证或完善的产品层能力包括：

- Codex 根据图片或正文主动生成话题候选，并在预览中结构化展示。
- 话题未全部选中时强制退回预览，而不是仅记录警告。
- 发布前对目标账号、媒体清单和最终话题进行统一确认。
- 对“发布结果不确定”建立明确状态，避免自动重试导致重复笔记。
- 对临时文件清理和日志脱敏建立可回归测试。
